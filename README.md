# الكتيبة الخامسة — خادم المزامنة الدقيقة

## المصادقة

الدخول محمي حصراً بمصادقة HTTP Basic على مستوى الخادم. لا توجد شاشة دخول محلية أو أدوار `admin` و`viewer` داخل الواجهة. كل بيانات مرور صحيحة تمنح صلاحية القراءة والكتابة نفسها، ويكون اسم المستخدم جزءاً من سجل التدقيق في كل عملية مزامنة.

اضبط أحد الخيارين التاليين في متغيرات Railway:

| الخيار | المتغيرات |
|---|---|
| حساب واحد | `BASIC_AUTH_USER` و`BASIC_AUTH_PASSWORD` |
| عدة حسابات متساوية الصلاحية | `BASIC_AUTH_USERS_JSON`، مثال: `{"name-one":"password-one","name-two":"password-two"}` |

## المزامنة الدقيقة

لم يعد الحفظ يرسل لقطة كاملة من كل البيانات. كل تعديل يصبح عملية مستقلة على سجل محدد، تحمل `opId` و`collection` و`recordId` و`baseRevision`. يقبل الخادم العملية فقط عندما تطابق نسخة السجل الحالية، ويعيد تعارضاً واضحاً إن سبق جهاز آخر بتعديل السجل نفسه. وبهذا تُدمج تعديلات السجلات المختلفة من الأجهزة المتعددة من دون كتابة أي تعديل فوق آخر.

| الواجهة | الوظيفة |
|---|---|
| `GET /api/sync/bootstrap?since=<sequence>` | يجلب العمليات الجديدة منذ آخر رقم تسلسلي على الجهاز. |
| `POST /api/sync/operations` | يرفع دفعة عمليات إنشاء أو تحديث أو حذف قابلة لإعادة المحاولة بأمان. |
| `GET /api/sync/stream` | بث فوري (Server-Sent Events) يُبلّغ كل جهاز متصل خلال أجزاء من الثانية بأي تعديل معتمد على أي سجل، فيجلبه فوراً دون انتظار. |
| `GET /api/sync-status` | يعرض حالة مخزن المزامنة الدقيق ومخزن البيانات القديم. |
| `GET /api/whoami` | يعرض اسم مستخدم الخادم الحالي لأغراض سجل العمليات فقط. |

تُدار تعارضات السجل من الواجهة عبر اختيار الاحتفاظ بالتعديل المحلي كنسخة جديدة أو اعتماد النسخة المحفوظة على الخادم.

### المزامنة الفورية بين الأجهزة

كل جهاز مفتوح يشترك تلقائياً في `/api/sync/stream`. لحظة قبول أي تعديل من أي جهاز (سواء إضافة أو تعديل أو حذف)، يُبلَّغ الخادم كل الأجهزة الأخرى المتصلة فوراً عبر هذا البث، فتجلب التعديل الجديد خلال أجزاء من الثانية بدل الانتظار. إن انقطع الاتصال (نوم الجهاز، تبديل الشبكة...) تعاد المحاولة تلقائياً من المتصفح، ويبقى استطلاع احتياطي كل 20 ثانية كشبكة أمان في حال فوات إشعار ما.

## إعداد Supabase

نفّذ محتوى `supabase_setup.sql` في محرر SQL الخاص بمشروع Supabase قبل أول نشر. ينشئ الملف جداول السجلات وسجل العمليات والدالة الذرية `apply_sync_operation`. بعد ذلك اضبط `SUPABASE_URL` و`SUPABASE_KEY` في Railway. يُستخدم تخزين محلي احتياطي فقط عند تعذر Supabase؛ يوصى بربط وحدة تخزين Railway دائمة وتعيين `DATA_DIR=/app/data` لحماية هذا الاحتياط.

## التشغيل والاختبار

```bash
npm install
npm test
BASIC_AUTH_USER=example BASIC_AUTH_PASSWORD=strong-password npm start
```

قبل النشر، لا تضع كلمات مرور تجريبية في المستودع. أضفها فقط في إعدادات متغيرات Railway الآمنة.
